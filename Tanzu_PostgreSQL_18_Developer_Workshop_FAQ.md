# Tanzu PostgreSQL 18 --- 3D Crime Scene Intelligence

## Developer Workshop FAQ

**Workshop:** VMware Tanzu PVE Team\
**Author:** Abhishek Jain\
**Repository:**
https://github.com/sendjainabhi/tanzu-pg18-crimescene-demo

This FAQ documents the workshop architecture and demonstration behavior.
SQL and implementation details are based on the workshop materials;
deployment-specific Tanzu capabilities and unverified application
behavior are identified where relevant.

## Tanzu PostgreSQL and architecture

### 1. Why use Tanzu PostgreSQL rather than community PostgreSQL?

Tanzu PostgreSQL combines the PostgreSQL ecosystem with enterprise
distribution, support, and deployment-specific operational integration.
PostGIS and pgvector are open PostgreSQL extensions, not Tanzu-exclusive
features. Validate operational capabilities for the particular Tanzu
offering.

### 2. What is the primary advantage of this application architecture?

Relational scene records, 3D spatial data, and investigation vectors can
be queried together in PostgreSQL. This can reduce synchronization
between separate databases.

### 3. Why not use a document database and a separate vector database?

That is a valid alternative. PostgreSQL is useful when transactions,
joins, spatial predicates, and vector ranking need to work together in
SQL.

### 4. Are PostGIS and pgvector new to PostgreSQL 18?

No. Both extensions predate PostgreSQL 18.

### 5. Does Tanzu PostgreSQL provide high availability and backups?

Availability of HA, backup, recovery, and upgrade automation depends on
the Tanzu PostgreSQL product, edition, and deployment configuration.

### 6. Can the demo run on community PostgreSQL?

Yes, if PostgreSQL, PostGIS, pgvector, application dependencies, and
configuration are compatible.

## 3D spatial storage and PostGIS

### 7. How are 3D locations stored?

PostGIS can store X, Y, and Z coordinates in geometry types such as
`geometry(PointZ, 0)`.

### 8. What does `(0, 0, 1.5)` represent?

The incident starts at the center intersection with a modeled elevation
of 1.5 units; the workshop assumes local scene units are meters.

### 9. How is `PointZ` different from `vector(384)`?

`PointZ` represents a 3D spatial position. `vector(384)` represents a
384-feature embedding for similarity search.

### 10. How is 3D distance calculated?

`ST_3DDistance` calculates 3D distance, and `ST_3DDWithin` checks
whether 3D geometries fall within a specified distance.

### 11. Why do examples use SRID 0?

SRID 0 denotes an unspecified coordinate reference system. The examples
assume a documented local coordinate system; production deployments
should choose an appropriate defined reference system.

### 12. Can PostGIS store 3D building geometry?

PostGIS supports geometries with Z coordinates, including points, lines,
and polygonal structures. A full visualization or solid-modeling engine
is a separate concern.

## Visibility, obstacles, and CCTV

### 13. Does visibility analysis run entirely in PostgreSQL?

No. In the described demo, PostGIS selects spatial candidates, Python
classifies facade orientation and modeled obstruction, and Three.js
renders results.

### 14. What do green, red, and amber windows mean?

Green: modeled visible. Red: modeled obstructed. Amber: not facing the
incident.

### 15. What happens when the Investigation Test Wall is disabled?

Its enabled state is updated in PostgreSQL. Rerunning visibility can
change classifications where that wall was an obstruction.

### 16. Does changing Maximum Displayed Rays change the visibility result?

The control is intended to limit displayed rays. Confirm the exact
behavior in the running application.

### 17. How does CCTV coverage analysis work?

The demo stores camera position and configuration, then uses spatial
proximity and simplified geometry to estimate potential coverage.

### 18. Can the demo prove that a witness saw an incident?

No. The demo uses simplified models and does not establish forensic
evidence or actual camera footage.

## pgvector and hybrid search

### 19. What is pgvector?

A PostgreSQL extension providing vector types, distance operators, and
vector indexing capabilities.

### 20. Why use 384 dimensions?

The workshop uses a fixed-length 384-dimensional representation of
investigation descriptions. This is an application choice.

### 21. Are the demo embeddings generated by an LLM?

The workshop describes a deterministic token-feature encoder rather than
a trained semantic embedding model.

### 22. What does `<=>` mean?

It is pgvector's cosine-distance operator. Lower distance indicates
greater cosine similarity.

### 23. What is hybrid search in this workshop?

A PostGIS spatial filter limits investigations by 3D distance; pgvector
then ranks the eligible records by cosine distance.

### 24. What changes when the radius increases from 30 to 100 meters?

The spatial candidate set can grow, potentially changing which
investigations are returned and their ranking.

### 25. Can pgvector store embeddings from other models?

Yes, when vector type, dimensions, and encoding consistency are
maintained.

### 26. Can relational filters, JSONB, PostGIS, and pgvector be used in one SQL query?

Yes. PostgreSQL supports combining these operations in SQL.

## Performance and scale

### 27. How can 3D spatial queries be optimized?

Use appropriate spatial indexes, filter candidates, maintain statistics,
and inspect actual query plans. Confirm index/operator compatibility for
3D predicates.

### 28. Is HNSW necessary for 60 investigations?

Not necessarily. Exact search may be simpler and faster for a small
dataset.

### 29. What is the difference between exact search and HNSW?

Exact search finds nearest results from the evaluated candidates. HNSW
accelerates approximate nearest-neighbor retrieval with a possible
recall tradeoff.

### 30. What does `EXPLAIN (ANALYZE, BUFFERS)` provide?

Observed query plan, execution timing, row counts, and buffer activity.

### 31. What timings should be distinguished in the demo?

Database round-trip time, Python visibility-processing time, and total
analysis time.

## Deployment and production readiness

### 32. How should Flask connect securely to PostgreSQL?

Use TLS where supported, least-privilege roles, secret management,
parameterized SQL, input validation, connection pooling, and timeouts.

### 33. What is required to deploy this application?

Deploy the Flask application and frontend, provision compatible Tanzu
PostgreSQL, apply migrations, configure networking and secrets, and
validate extensions, monitoring, and recovery.

### 34. What happens when the embedding encoder changes?

Old and new vectors may not be comparable. Track encoder versions and
regenerate embeddings when required.

### 35. Can multiple investigators use the application concurrently?

PostgreSQL supports concurrent transactions, but the application must
define authorization, shared state, and conflict handling.

## Architecture review questions

### 36. What does Tanzu add if PostGIS and pgvector are open source?

Enterprise packaging, support, and supported operational lifecycle are
the differentiators to evaluate for the chosen Tanzu product; the
extensions themselves are not proprietary.

### 37. Why use PostGIS if Python performs visibility classification?

PostGIS stores and filters spatial data; Python applies the
application-specific facing and obstruction rules.

### 38. Is this an AI demo if it uses a deterministic encoder?

It is primarily a spatial-intelligence and vector-search demo.
Production semantic retrieval would require a suitable trained embedding
model and quality evaluation.

## Workshop demonstration checklist

-   Initial scene: Overview; building opacity 30%; Move Incident OFF;
    incident at `(0, 0, 1.5)`.
-   Smart Visibility: green, red, and amber window categories; compare
    5, 10, and 20 displayed rays.
-   Obstacles: disable and restore Investigation Test Wall, rerunning
    visibility.
-   CCTV: analyze potential coverage and show/hide sectors.
-   Similar cases: search `vehicle obstruction witness`.
-   Hybrid search: compare radii of 30, 50, and 100 meters.
-   SQL Inspector and Query Performance: inspect spatial/hybrid SQL and
    application timings.
